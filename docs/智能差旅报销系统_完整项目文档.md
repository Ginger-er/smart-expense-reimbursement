# 智能差旅报销系统 —— 完整项目文档

> **项目定位**：企业级智能差旅报销管理平台
> **核心能力**：AI发票识别 · 智能审批流 · 费用异常预警
> **设计风格**：高级简约 · 专业克制 · 信息优先

---

## 一、项目概述

### 1.1 一句话定义
企业员工出差后，拍照上传发票，系统自动识别并生成报销单，按规则流转审批，超支或异常时AI预警。

### 1.2 目标用户
- **员工**：快速提交报销，减少手工填单
- **直属领导**：网页端审批，查看异常标记
- **财务管理员**：异常预警监控，批量导出报表

### 1.3 核心场景

场景1：员工小张出差3天，拍了5张发票 → 上传 → AI识别 → 自动归集到本次出差 → 生成报销单 → 提交审批

场景2：财务李姐每天9点收到系统推送 → 3条异常报销待复核 → 点击看AI生成的风险摘要 → 决定通过/驳回

场景3：领导王总登录后台 → 查看发票图片+识别结果 → 一键通过/填写驳回原因

## 四、核心功能模块设计

### 4.1 模块一：发票智能识别

#### 4.1.1 流程时序

```
用户 → 拍照上传发票 → 前端 → POST /invoice/upload → 后端
  → 保存图片到MinIO → 返回fileUrl
  → 调用百度OCR API → 返回识别结果
  → 数据校验层:
      ├ 金额=明细求和
      ├ 日期≤今天
      └ 发票代码校验位
  → 保存发票记录 → 数据库
  → 返回识别结果+校验状态 → 前端 → 显示识别结果
用户 → 确认/修正 → POST /invoice/confirm → 更新状态+关联trip
```

#### 4.1.2 核心校验规则

| 校验项 | 规则 | 失败处理 |
|--------|------|----------|
| 金额一致性 | 发票金额 = 明细金额求和 | 标记"校验失败"，提示用户核对 |
| 日期有效性 | 开票日期 ≤ 当前日期 | 标记异常，允许人工确认 |
| 发票代码校验 | 按国标校验位算法验证 | 标记"疑似假票"，需人工复核 |
| 重复报销检测 | 同一发票代码+号码已存在且已报销 | 直接拦截，提示"该发票已报销" |
| 关联合理性 | 开票日期应在出差日期范围内 | 标记异常，需填写说明 |

### 4.2 模块二：报销单生成与审批流

#### 4.2.1 审批流程图（BPMN）

```
┌─────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────┐
│  开始   │───►│  直属领导   │───►│  部门经理   │───►│  财务总监   │───►│  结束   │
└─────────┘    └──────┬──────┘    └──────┬──────┘    └──────┬──────┘    └─────────┘
                      │                  │                  │
                      ▼                  ▼                  ▼
                 ┌─────────┐      ┌─────────┐      ┌─────────┐
                 │ 驳回/   │      │ 驳回/   │      │ 驳回/   │
                 │ 转办    │      │ 转办    │      │ 转办    │
                 └─────────┘      └─────────┘      └─────────┘

条件分支:
- 金额 < 1000元：直属领导审批后直接结束
- 1000 ≤ 金额 < 5000元：直属领导 → 部门经理
- 金额 ≥ 5000元：直属领导 → 部门经理 → 财务总监
```

#### 4.2.2 状态机

```
草稿(0) → 提交 → 待审批(1) → 启动流程 → 审批中(2) → 全部通过 → 已通过(3) → 打款 → 已打款(5)
                                                      ↓ 驳回
                                                  已驳回(4) → 重新提交 → 草稿(0)
```

#### 4.2.3 核心接口

| 接口 | 方法 | 说明 |
|------|------|------|
| /reimbursement/create | POST | 创建报销单（从trip归集invoice） |
| /reimbursement/submit | POST | 提交审批（启动Camunda流程） |
| /reimbursement/approve | POST | 审批通过/驳回（推进流程节点） |
| /reimbursement/list | GET | 查询报销单列表（分页+状态筛选） |
| /reimbursement/detail | GET | 报销单详情（含审批历史） |

### 4.3 模块三：费用异常预警

#### 4.3.1 预警规则配置

| 规则编码 | 规则名称 | 触发条件 | 风险等级 |
|----------|----------|----------|----------|
| A001 | 金额突增 | 同员工同类型本月金额 > 上月150% | 中 |
| A002 | 限额擦边 | 单张发票金额 > 标准限额90% | 低 |
| A003 | 重复发票 | 同一发票代码+号码重复出现 | 高 |
| A004 | 日期异常 | 开票日期不在出差日期范围内 | 中 |
| A005 | 高频报销 | 同一员工7天内提交>3次报销 | 低 |

#### 4.3.2 定时任务

```
任务名称：expense-abnormal-scan
执行频率：每天 09:00（工作日）
执行逻辑：
  1. 扫描昨日00:00至今日00:00的所有新提交/通过的报销单
  2. 逐条匹配A001-A005规则
  3. 命中规则则写入abnormal_record表
  4. 调用DeepSeek API生成预警摘要
  5. 推送消息给财务管理员（企业微信/站内信）
```

>
> 核心功能有三个：
> 第一，发票智能识别。用户拍照上传后，调用百度OCR提取信息，后端做二次校验，比如金额一致性、日期有效性、重复报销检测，识别准确率能做到95%以上。
>
> 第二，智能审批流。我用Camunda设计了多级审批流程，根据金额自动判断审批节点，全部配置化，支持会签、转办。审批状态变化全程留痕。
>
> 第三，费用异常预警。每天定时扫描报销数据，匹配五条异常规则，比如金额突增、限额擦边、重复发票，命中后调用DeepSeek生成预警摘要推送给财务。
>
> 技术栈是Spring Boot 3 + Vue3 + Camunda + Redis + XXL-Job，前后端分离部署。"

### 10.2 高频面试问题

| 问题 | 回答要点 |
|------|----------|
| "OCR识别失败了怎么办？" | 降级方案：允许手动填写，记录失败原因；批量失败切换备用OCR |
| "高并发扣减怎么保证安全？" | Redis分布式锁(Redisson) 或 DB乐观锁(version字段) |
| "审批流驳回后重新提交？" | 状态机：驳回→草稿→重新提交→重新走审批；保留历史记录，显示"第2次提交" |
| "AI hallucination 怎么办？" | 后处理校验：金额非负、分类在枚举范围、长度限制；异常返回默认文案 |
| "用户量大了怎么扩展？" | 无状态设计水平扩展；DB读写分离；Redis缓存热点；对象存储文件 |
| "Camunda和状态机区别？" | Camunda支持BPMN可视化、会签/或签、历史流程查询、超时提醒 |
